# Local dataset acquisition and rendering

The adapters read local files. They do not download datasets, accept access gates, start games, execute replay inputs, or install upstream packages. Public access does not imply unrestricted reuse. Record the release URL, access date, game/build, file hashes, original rights notice and transformations for each acquired subset. Code licenses and media licenses can differ. Keep full datasets and private path worksheets outside version control.

The statuses below describe the upstream release and the supported local representation. A local `inspect` result describes only the files visible at the supplied root: `available`, `partial_available`, `archives_only`, `replay_only`, `gated_missing_assets`, `missing`, or `invalid`. Follow its findings; a truncated scan is not a complete inventory.

## Safe local workflow

1. Select a small authorized subset from the primary release. Save its source and rights notice; acquire it manually using a reviewed method. There is no bulk acquisition helper in v1.
2. Keep original files immutable. Index a separate local data root; do not place downloaded scripts in the source package. Headers and paths are checked within finite bounds. Most adapters expect unpacked data; Slippi alone supports bounded direct reads of its TAR shards. The CLI does not extract archives. Do not enable pickle to work around a MineRL finding.
3. Run `inspect`, then `index` with a small limit, then `validate`. Add `--decode` only when the required reader extras are present. For StarCraftImage and Dota2-Vis, use `--unit frames --start 0 --end 1`; for Proact, use `--unit seconds` and a known source-video interval. Slippi returns telemetry and, only with a valid rendered manifest, linked RGB.
4. Check frame/action counts, native timestamps, missing assets, duplicate lineage and every conversion in the annotation ledger. An indexed file is not a verified temporal alignment. Keep SHA-256s for source files and derivative exports.

## Melee and AoE II DE capture for the pilot

Rendering is a separate, manual acquisition step. Choose a compatible game/build, platform and replay tool, and capture a small reviewed replay or expert demonstration. Keep the raw replay independently. Record renderer/build, camera/viewpoint, playback speed, frame rate, audio policy, overlays, native game frame/tick origin, encoded PTS origin and any dropped/duplicated frames. Verify alignment with visible and telemetry events at the start, middle and end. Do not infer alignment just from equal lengths.

The Slippi adapter never renders replays. To attach an already captured local Melee video, create root `rendered_manifest.jsonl`, one row per replay content hash:

```json
{"replay_sha256":"REPLACE_WITH_64_HEX_DIGITS_FROM_INDEX","video_path":"renders/match-001.mp4","video_start_frame":-123,"game_version":"RECORD_ACTUAL_GAME_BUILD","fps":60,"renderer":"RECORD_RENDERER_AND_BUILD","provenance":{"alignment_review":"RECORD_VISIBLE_AND_TELEMETRY_CHECKS"}}
```

`video_start_frame` is the native Slippi frame ID shown by video index 0; the negative value above is an example only. The default mapping asserts exactly one video frame per native NTSC 60-Hz frame. PAL, other capture rates, dropped frames or repeated frames require explicit `frame_map`, for example `[{"video_index":0,"native_frame":-123},{"video_index":1,"native_frame":-122}]`, covering the relevant source-video indices. Indices must increase; native frames may repeat but cannot decrease. Index 0 must agree with `video_start_frame`. This is a user-supplied alignment claim that requires review; equal durations do not establish it. Rendered frame `index` and `video_index` both identify the unique video capture frame; `frame_id` and `timestamp` use native Slippi time, and encoded PTS/video timestamps remain separate. Model-facing `required_indices` therefore select video capture indices; native-frame requests must be translated through the manifest, retaining repeated captures explicitly. Sparse maps cover only listed frames. Requested decoded spans cannot exceed 4,096 video frames. Unmatched hashes, exact duplicate rows and conflicts appear as findings; conflicting mappings disable RGB attachment. Without a valid mapping, `Window.frames` remains absent. This project includes no Dolphin, game images or rendering wrapper.

`mine-candidates` (Slippi only) reads telemetry windows in bounded overlapping chunks and proposes review windows for wavedash, L-cancel, dashdancing, short hop and edgehogging. Rule IDs, thresholds and transcribed action-state constants are recorded on every candidate. Check each replay's state histogram in the mining manifest before trusting the constants. The adapter additionally reads the post-frame `l_cancel` and `velocities.*` fields when the parser exposes them (field names unverified against peppi-py 0.8.6). Group replays of one set/session with `--sessions` (replay SHA-256 → session ID); otherwise only replay-level lineage is known.

AoE exports use paths relative to the supplied data root, for example:

```json
{"video_path":"renders/match-001.mp4","replay_path":"replays/match-001.aoe2record","events_path":"sidecars/match-001.events.jsonl","states_path":"sidecars/match-001.states.jsonl","actions_path":"sidecars/match-001.actions.jsonl","fps":30,"source_replay_id":"local-match-001","time_unit":"seconds","game":"Age of Empires II: Definitive Edition","game_version":"RECORD_ACTUAL_GAME_BUILD","recorded_game_version":"RECORD_ORIGINAL_REPLAY_BUILD","rendered_game_version":"RECORD_PLAYBACK_BUILD","dataset_revision":"LOCAL_EXPORT_REVISION","source":{"url":"RECORD_ACTUAL_SOURCE","rights":"RECORD_APPLICABLE_TERMS"}}
```

Omit unavailable replay/sidecar paths rather than inventing labels. `game_version` is the actual game edition/patch; `dataset_revision` is the export revision. A generic manifest `version` is not interpreted as a game build. The adapter reports a finding when provided `recorded_game_version` and `rendered_game_version` differ, and warns when game version is unknown. Sidecar rows must use `timestamp` for seconds or `index` for frames, matching `time_unit`; no more than 4,096 sidecar rows in total are returned per window. The frame rate above is an example capture rate, not an assumed game clock. Use a common export origin and record any replay/game-time conversion, pause or speed change. Events and recorded commands describe observed behavior; expert-approved alternatives and a task validator are separate evidence.

For KBD/FC/ISG or similarly precise terms, expert demonstrations with positive, near-miss and wrong-context examples are often more useful than an unannotated large corpus. Fix the title/version and independently review meanings before recording. Preserve forum usage evidence separately from video annotation, and log later agent exposure separately from both.
